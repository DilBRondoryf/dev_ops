Логи и доступность

Добавлен рабочий `compose.student.yaml` с образами `devops-student:local`, API, web, общим томом `requests` и healthcheck.
Запуск: `docker compose -f compose.student.yaml up -d`
`api` и `web` стали `healthy`, web опубликован как `127.0.0.1:8080->8000/tcp`.

Сценарий

Команды

GET  http://localhost:8080/health
POST http://localhost:8080/api/requests
     {"kind":"screen","key":"kt4-k401-dames"}
GET  http://localhost:8080/api/requests
docker compose -f compose.student.yaml logs --tail=30 api
docker compose -f compose.student.yaml logs --tail=30 web

Наблюдение

2026-11-21T17:51:52.3397649+03:00 GET /health -> {"process":"running","role":"web"}
2026-11-21T17:51:52.3972574+03:00 POST -> 201, request id=1
2026-11-21T17:51:52.4030878+03:00 GET /api/requests -> total=1

В логах контейнеров время указано в UTC: `14:51:52.394953Z` в `api` содержит `request_accepted`, а `14:51:52.395038Z` содержит `POST /api/requests` со статусом 201. В `web` за тот же запрос есть `14:51:52.395382Z` и статус 201. Разница с локальным временем +03:00 объясняется часовым поясом логов контейнера.

`/health` проверяет, что процесс отвечает, поэтому web может вернуть 200 даже при недоступном API. Проверка зависимости проявляется на функциональном `GET /api/requests`: web проксирует запрос, получает ошибку upstream и возвращает 503 с `upstream_unavailable`. При старте Compose зависимость дополнительно проверяется условием `api: service_healthy`.

Вывод: успешная заявка прошла через web в api, запись попала в общий том, а логи обоих сервисов связываются по времени и пути запроса.
Ответ на вопрос: отказ зависимости заметит проверка, которая вызывает зависимый endpoint (`/api/requests`), а не локальный `/health` web.
