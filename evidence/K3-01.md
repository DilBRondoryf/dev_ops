# K3-01. CI/CD and branches

## Flow

```text
short-lived branch
        |
        v
commit and push -> pull request to main in the student's fork
                           |
                           v
                      Student CI
                      |       |
                      v       v
                    test --> build
                              |
                              v
                        review and merge
```

`push` and `pull_request` start the workflow. The `test` job checks the application with the integration suite. The `build` job has `needs: test`, so it runs only after a successful test job. A test failure is reported by Actions in the failed step; the dependent build is then `skipped`.

CI means automatically checking changes as they are integrated. Continuous Delivery prepares a verified change for a controlled release. Continuous Deployment automatically deploys a verified change to the target environment.

This workflow implements CI and part of delivery: tests and Docker image build. Building an image is not deployment because the image is not pushed to a registry and is not started in the target environment.

Git-flow adds long-lived `develop` and `release` branches and extra branch transitions. A short-lived branch and a PR to `main` are easier to follow for a small course project while preserving review and fast feedback.
