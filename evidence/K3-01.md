# K3-01. CI/CD и ветки

## Схема работы

```text
короткая ветка
       |
       v
commit и push -> pull request в main своей копии
                         |
                         v
                    Student CI
                    |       |
                    v       v
                  test -> build
                            |
                            v
                       review и merge
```

После push или создания pull request запускается Student CI. Job `test` получает код, устанавливает Python и запускает тесты приложения. Job `build` зависит от `test` через `needs: test`, поэтому запускается только после успешных тестов. Если тесты падают, ошибка видна в Actions на упавшем шаге, а build получает статус `skipped`.

CI нужен для автоматической проверки изменений. Continuous Delivery подготавливает проверенное изменение к управляемому выпуску. Continuous Deployment автоматически выкладывает проверенное изменение в целевую среду.

В этой работе есть CI и часть delivery: тестирование и сборка Docker-образа. Сама сборка образа не является deployment, потому что образ не отправляется в registry и не запускается в рабочей среде.

В Git-flow были бы дополнительные долгоживущие ветки `develop` и `release`. Для небольшой учебной работы это усложняет процесс. Короткая ветка и PR в `main` проще, при этом остаются проверка и code review.
