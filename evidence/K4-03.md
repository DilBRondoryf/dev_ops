Ansible и повторный запуск

Использованные команды

docker compose -f compose.student.yaml run --rm ansible demo.yml
docker compose -f compose.student.yaml run --rm ansible demo.yml
docker compose -f compose.student.yaml run --rm ansible banner.yml
docker compose -f compose.student.yaml run --rm ansible banner.yml
docker compose -f compose.student.yaml run --rm ansible banner.yml
GET http://localhost:8080/api/banner

Для `demo.yml` первый запуск дал `ok=1 changed=1`, второй `ok=1 changed=0`. Для banner первый запуск также дал `changed=1`, повторный запуск до изменения переменной дал `changed=0`.

В [ansible/banner.yml](../ansible/banner.yml) задана переменная:

workshop_message: "DevOps workshop student: dames | KT4 monitoring ready"

Задача `ansible.builtin.copy` записывает её в `/data/banner.txt` с `mode: "0644"`, `owner: "10001"` и `group: "10001"`. Проверка файла показала:

644 10001 10001 /data/banner.txt

После изменения сообщения третий запуск дал `changed=1`, а API вернул:

{"message":"DevOps workshop student: dames | KT4 monitoring ready"}


Inventory задан прямо в entrypoint образа Ansible как `localhost,`, а `connection: local` запускает модуль внутри временного контейнера. SSH не нужен: файл доступен через общий volume `requests`, смонтированный в `/data`. Для удалённого сервера понадобились бы его адрес в inventory, SSH connection plugin/порт, пользователь и ключ или другой способ аутентификации.

Вывод: повторный запуск без изменений идемпотентен, а изменение переменной применяется и видно через web/API.
